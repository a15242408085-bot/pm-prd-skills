# 产品需求工作流

先检查已有材料和用户指定步骤。默认短链为问题定义 → PRD → 自检；用户需要指标、风险、AI 评测或上线建议时再追加相关阶段。已有合格产物直接复用。

## 路由

| 材料／任务 | 使用技能 |
| --- | --- |
| 原始反馈需要整理 | pm-voc |
| 需求起草或修订 | pm-prd |
| PRD 自检或评审 | pm-lint |
| 指标与口径 | pm-metrics |
| 事前风险推演 | pm-premortem |
| AI 评测设计 | pm-eval |
| 已有 runner 的评测执行 | pm-run-eval |
| 执行记录复盘 | pm-transcript-review |
| 上线建议 | pm-launch-readiness |
| 一页决策摘要 | pm-brief |

按需要加载对应技能及资源。完整链需要上述技能同时可用；缺少技能时明确缺口，仍可完成独立阶段，不假装成功调用。

## 衔接与停止条件

- 维护简短索引，记录产物位置、版本、状态以及 `SRC → PROB → REQ → AC → CASE` 映射。已有编号不重排。
- 指标与风险变化回写 PRD 的建议；用户授权修改时再更新正文，不把彼此矛盾的多份结论交付。
- 将影响后续步骤的未知条件集中列出，继续完成不依赖答案的阶段。外部副作用不由链式指令隐含扩张授权。
- 自检后的修订默认最多两轮；若仍有业务缺口，交付草稿与待确认项。用户明确要求其他轮数时按其要求。
- 未接入 runner 时停在“评测设计完成、未运行”；无真实证据时不能给 GO。禁止后台无限循环、自动部署或自行联系他人。

最终交付索引、正文／资源与阻断项，简洁说明完成哪些步骤、哪些仍需证据。
