# 用户反馈整理

先读原材料，保留渠道和来源编号。将“用户说了什么、实际受阻是什么、期望结果是什么、建议方案是什么”分开。转述不升级为用户原话，摘要不替代原始证据。

## 工作方法

1. 为每条材料分配 `SRC-001` 等编号，记录渠道、时间、角色和原文定位。复用已有编号。
2. 按困难和期望结果聚类；同一人、同一事件的重复反馈合并计数，同时保留原始条数和独立用户／事件数。身份缺失时说明无法去重。
3. 逐个主题说明发生频率、损失严重程度、产品匹配度和证据可信度。非代表性样本不外推总体比例；没有量化证据时采用定性排序。
4. 区分事实、假设、待确认。低频但高损失的失败单独保留。未知用户规模、收入影响和频率不估成事实。
5. 选一个可进入 PRD 的主问题，列出支持出处、相邻问题、非目标和下一步需要核实的数据。

## 输出

- 信号表：来源编号、渠道、原话／摘要、用户困难、期望结果、证据限制。
- 问题表：`PROB-ID`、问题、人群、来源编号、去重口径、优先级理由、待验证假设。
- 主问题与研究缺口；若存在坏案例，保留输入、实际输出和真实后果。

缺失材料时先请求原始反馈；只有想法时可以形成待验证的问题假设，注明尚无用户证据。发布或外传材料前沿用用户授权范围，示例使用脱敏或虚构数据。
