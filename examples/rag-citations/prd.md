# 企业 RAG 引用溯源 PRD

版本 demo-v1 · 草稿 · 负责人待确认。全部为虚构示例。

## 1. 问题与目标

企业知识库用户需要核查答案，当前存在无法定位原文、权限与显示不一致及失败无出口的问题。来源为 SRC-001～SRC-004，对应 PROB-001。

事实仅限示例输入中的反馈内容；用户规模、业务损失、现有系统能力均未知。假设“可核查来源有助于建立信任”，需访谈和行为数据验证。

## 2. 方案与范围

在有证据的答案中展示来源卡片，包含文档名、PDF 文件页序与证据片段；点击时重新校验权限并查看原文。普通文本仅展示章节定位，无页码时不猜测。租户和角色权限在检索、生成、片段展示及点击时均生效。

本版不做自动权限申请、跨租户检索、网页资料引用和自动写入知识库。知识更新机制、引用与文档版本绑定由研发确认；若版本变化导致定位失效，提示“资料已更新，请重新提问”。

| 需求 | 来源 | 能力 | 优先级 | 验收 |

| REQ-001 | SRC-001 | 有依据时展示可验证引用 | Must | AC-001 |
| REQ-002 | SRC-002 | 多阶段权限校验及租户隔离 | Must | AC-002 |
| REQ-003 | SRC-003 | 证据不足时明确说明，不编造 | Must | AC-003 |

| 验收 | 前置条件与动作 | 可观察结果／证据 | 关键 |
| --- | --- | --- | --- |
| AC-001 | 用户有权限，fixture 的 policy.pdf 第 3 文件页存在支持结论的片段，提问后点击引用 | 文档 ID、版本、页序与 fixture 匹配；引用片段支持答案，链接打开对应页 | 是 |
| AC-002 | 用户属于 tenant-a，仅有 tenant-b 的目标资料；提问并尝试查看来源 | 回答、引用片段、工具响应均不泄露 tenant-b 内容；直接访问仍拒绝，保存权限检查证据 | 是 |
| AC-003 | 提问涉及不存在知识；另用证据充分的相邻问题对照 | 无证据明确说明不足且无虚构引用；证据充分的对照应正确回答并给引用 | 是 |
| AC-004 | fixture 模拟引用服务超时，用户点击引用 | 达到已配置超时后展示错误与重试／退出；不声称已加载；重试按需去重，不影响原答案 | 否 |
| AC-005 | 引用绑定文档版本 v1，源文档改为 v2 且内容页序变动 | 旧引用标失效或重定位经验证的证据，不把旧页码冒充新版本定位 | 是 |

AC-005 尚未编写评测任务，是明确覆盖缺口。示例演示不能完成真实验收。

## 4. 用户流程与约束

主流程为提问 → 按租户／角色检索 → 核查支持关系 → 生成答案与引用 → 点击时再次验权 → 查看证据。

| 状态 | 系统行为 | 关联验收 |
| --- | --- | --- |
| 初始空状态 | 显示提问入口和支持的资料范围 | REQ-001 |
| 加载中 | 显示进度，允许取消引用查看 | AC-004 |
| 成功 | 展示文件页序、片段和文档版本 | AC-001／AC-005 |
| 无证据 | 说明资料不足，允许补充信息；无来源卡片 | AC-003 |
| 无权限／跨租户 | 不泄露资料内容与可用链接，提示联系管理员的合规入口 | AC-002 |
| 引用超时 | 展示重试与退出，不冒充加载成功 | AC-004 |
| 资料更新 | 标失效并建议重新提问 | AC-005 |

性能目标、超时值、知识更新频率和成本上限均待确认。人工入口、服务时间和容量待客服确认，不能以“转人工”代替完整方案。

## 5. 指标与验证

| 指标 | 定义 | 事件／窗口 | 目标与状态 |
| --- | --- | --- | --- |
| METRIC-001 核查任务完成率 | 用户成功查看经核查证据的独立任务数 / 发起引用查看的独立任务数 | citation_open_requested、citation_open_succeeded；按 task_id 去重；周窗口 | 基线、目标待确认；零分母为无数据 |
| METRIC-002 引用支持率 | 经人工抽检支持答案的引用数 / 被抽检引用数 | 抽样台账，记录抽样范围与样本量；周窗口 | 基线、目标、样本量待确认 |
| METRIC-003 引用加载 P95 | 以一次引用打开请求到成功显示证据的时长分布取 P95；失败率单列 | 同一 request_id 关联，按客户端和网络分群 | 性能阈值待研发确认 |
| METRIC-004 越权暴露护栏 | 经确认的越权暴露事件数；不被成功率抵消 | 权限审计与报告；灰度持续监控 | 任一确认事件停止灰度的规则为建议，待批准 |

事件只含匿名 task_id、request_id、tenant_id、document_id、版本和状态，不默认保存原始对话。字段保留范围由团队确认。

AC-001～AC-004 对应 CASE-001～CASE-004，AC-005 待补。
