# 运行与汇总评测

先确认 Suite、目标系统、runner／adapter、环境与调用预算。沿用已有授权；只有实际接入的工具才能执行模型评测。没有 runner 时完成运行计划和输入校验，明确“未运行”及缺少的接入信息。

## 执行

1. 固定 Suite 与评分器版本，记录模型、Prompt、工具、数据版本和执行时间。将用户授权的测试环境与生产环境区分。
2. 每个 Task 按约定重复运行，重置 fixture、缓存和状态；记录 Trial 编号。任何有副作用的测试都沿用用户的具体授权范围。
3. 每轮保存 Transcript、真实 Outcome、评分结果和错误。基础设施错误、待人工评分和未执行任务不能补成通过，也不能直接归咎模型。
4. 不足预算、持续接入失败或需要新增授权时停止依赖步骤；保留已完成证据与续跑计划，不无限重试。

## 结果汇总

使用团队 runner 的报告。若使用 `pm-prd-eval/v1`，可运行本技能附带的 [结果汇总器](scripts/summarize_eval.py)：

```sh
python3 <本技能目录>/scripts/summarize_eval.py --suite <suite.json> --results <results.json>
```

它仅汇总已有记录，不执行模型。输入格式由 `pm-eval/references/eval-format.md` 说明；使用时需与该技能配套，或读取仓库中的同名格式说明。

报告列出计划／完成数、已评分通过率、关键失败、不完整项与环境错误。任何关键失败不得被平均分抵消；未批准的阈值不生成已批准门槛结论。使用模拟数据时清晰标“演示”，不能作为真实上线证据。

模型或配置比较要求相同任务、评分规则和环境；不同口径的分数仅分别展示。最后交给记录复盘与上线判断，不能把质量门槛通过等同于产品获准上线。
